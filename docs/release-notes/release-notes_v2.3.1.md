# Release Notes v2.3.1

- リリース日: 2026-08-19
- 前バージョン: v2.3.0

## 概要

v2.3.1 では、Markdown のインライン解析におけるバックスラッシュエスケープの不具合を修正しました。  
主に `\*` を含むテキストが、意図せず強調記号として解釈される問題を改善しています。

本リリースは **バグ修正のみ** であり、既存仕様を変更するものではありません。

---

## 修正内容

### 1. エスケープされたアスタリスク (`\*`) の誤解析を修正

インライン解析において、`\*` が「文字としての `*`」ではなく、強調記号の一部として誤って扱われる場合がありました。  
この問題により、以下のようなケースで出力結果が期待と異なることがありました。

#### 修正前の例

- `**a\*b**`
  - `a*b` ではなく、`\*` を含んだ不正な見た目になる
  - 一部が斜体として解釈される場合がある
- `c\*d`
  - `c*d` ではなく `c\*d` のまま出力される
- `* **e\*f**`
  - 箇条書き内で `e*f` が正しく太字にならない
- `* g\*h`
  - 箇条書き内で `g*h` ではなく `g\*h` が出力される

#### 修正後の例

- `**a\*b**` → `a*b`（太字）
- `c\*d` → `c*d`
- `* **e\*f**` → `・ e*f`（`e*f` が太字）
- `* g\*h` → `・ g*h`

---

## 改善内容

### 2. 検証Markdownを更新

再発防止のため、`verify-paragraph-rendering.md` に以下の確認パターンを追加しました。

#### normal paragraph
- escaped asterisk inside strong emphasis
- escaped asterisk in plain text

#### bullet list paragraph
- bullet item escaped asterisk inside strong emphasis
- bullet item escaped asterisk in plain text

## 互換性

- 後方互換性に影響する変更はありません
- 既存の Markdown 変換仕様は維持されます
- 本リリースは **v2.3.0 の不具合修正版** です

---

## アップデート推奨

v2.3.0 を利用している場合は、`\*` を含む Markdown の変換結果を正しくするため、**v2.3.1 への更新を推奨** します。

---

## 対象ユーザー

特に以下に該当する場合、本バージョンの適用を推奨します。

- 本文中に `\*` を含む Markdown を扱う
- 箇条書き内で `\*` を含むテキストを扱う
- 太字や斜体とエスケープ記号を組み合わせた表現を使う
- Markdown の変換結果を仕様書・設計書として Excel 出力している
