# Release Notes - v2.1.4 (2026-04-23)

## 概要

v2.1.4 では、Markdown のコードフェンス解析に関する不具合を修正しました。  
4 連以上のバッククォートで囲まれたコードブロック内に 3 連バッククォートを含む場合、内側の 3 連バッククォートが誤ってコードブロック終端として解釈されることがありました。

本バージョンでは、開始フェンスの種類と長さに基づいて終端判定を行うよう修正し、コードブロック内のリテラル文字列を正しく Excel に出力できるようになりました。

---

## 主な修正内容

### 修正: コードフェンス終端の誤判定

コードブロック開始時のフェンス情報（記号種別・本数）を保持し、閉じフェンスを以下の条件で判定するよう修正しました。

- 開始フェンスと同じ記号であること
- 開始フェンス以上の本数であること
- フェンス後続が空白のみであること

これにより、たとえば 4 連バッククォートで囲まれたコードブロック内の ` ```java ` や ` ``` ` を、終端ではなく本文として正しく出力できます。

### 修正: コードブロック装飾の欠落

上記の誤判定により、コードブロックの途中行に対して背景色や罫線が適用されない場合がありました。  
本修正により、コードブロック全体に対して一貫して背景色・罫線が適用されます。

---

## 修正例

以下の Markdown を入力した場合:

`````md
## a

````text
b
```java
foo()
```
c
````
`````

v2.1.3 では、内側の ` ```java ` および ` ``` ` がコードフェンスとして誤認識され、Excel 出力結果が崩れる場合がありました。

v2.1.4 では、以下のように正しく出力されます。

- ` ```java ` をリテラル文字列として出力
- ` foo() ` をコード本文として出力
- ` ``` ` をリテラル文字列として出力
- コードブロック全体に背景色と罫線を適用
