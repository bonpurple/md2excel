# v2.4.0 リリースノート

- リリース日: 2026-09-17
- 前バージョン: v2.3.1

## 概要

v2.4.0では、Markdown解析とExcel描画の不具合を修正するとともに、内部構造を大幅に整理しました。

テーブル判定、コードブロック、ネストした引用の描画精度を改善し、JUnit 4による自動テストを追加しています。

---

## 主な改善

### テーブル判定の精度向上

未エスケープの`|`を含むだけの通常文が、誤ってテーブルとして扱われる問題を修正しました。

テーブルは、ヘッダー候補行の次に有効な区切り行がある場合に開始されます。

```markdown
price | note
```

上記は通常段落として扱われます。

```markdown
Name | Value
--- | ---
A | 100
```

上記はテーブルとして扱われます。

### ネストした引用の描画改善

ネストした引用内の次の要素を、それぞれ適切なブロックとして描画できるようにしました。

- 見出し
- 水平線
- 箇条書き
- 番号付きリスト
- テーブル

引用深度に応じて、左罫線と本文の列位置も調整されます。

### コードブロックの改善

- 閉じフェンスがないままEOFへ到達した場合も、コードブロックの外周枠を確定
- コード行にタブが含まれていても例外が発生しないよう修正
- コード本文に残るタブを半角スペース4個へ展開
- 開始フェンスのインデントのみをコード本文から除去

### 設定値の検証

GUIから入力する設定値に範囲チェックを追加しました。

- シート列数: 3～16,384
- フォントサイズ: 5～72 pt

不正な値や数値以外が入力された場合は、警告を表示して再入力を求めます。

---

## 不具合修正

- 親ディレクトリ名に`.`が含まれる場合、出力ファイルの拡張子を誤って置換する問題を修正
- タブを含むコード行で`substring()`の範囲外例外が発生する可能性を修正
- EOFで終了するコードブロックに外周枠が設定されない問題を修正
- ネストした引用内の見出しなどが通常文として描画される問題を修正
- ネストした引用内テーブルのデータ行が通常段落になる問題を修正
- 通常文中の`|`がテーブルとして誤認される問題を修正

---

## 内部構造の改善

保守性とテスト容易性を向上させるため、次のリファクタリングを実施しました。

- 起動処理、設定UI、Excel変換処理を分離
- コードブロック状態とテーブル状態を`RenderState`から分離
- Markdown行解析を`MarkdownLineParser`へ集約
- インラインコード境界の解析を共通化
- 列位置計算、引用空行生成、セル生成処理を共通化
- スタイル生成を`MdStyleCatalog`と各Factoryへ分離
- POIのスタイル番号ではなく、Markdown上の意味情報から引用スタイルを決定
- フォントキャッシュを静的領域から`RenderContext`配下へ移動
- 設定値クラスで入力値の妥当性を保証

これらは主に内部実装の変更であり、通常のGUI操作方法に変更はありません。

---

## テスト

JUnit 4による自動テストを追加しました。

主な確認対象は次のとおりです。

- Markdown文字処理
- インラインコードと`<br>`の判定
- コードフェンス
- リスト深度
- テーブル開始判定
- ネストした引用
- 設定値の検証
- Excel上のセル値・列位置・フォント・罫線
- EOFで終了するコードブロック
- コードブロック内のタブ展開

自動テストは次のクラスから実行できます。

```text
md2excel.AllTests
```

`docs/verify-paragraph-rendering.md`によるExcel出力の目視確認も実施済みです。

## 互換性

- Java 8以上
- 出力形式は引き続き`.xlsx`
- 出力シート名は引き続き`spec`
- 出力開始位置は引き続きB2
- GUIによる操作方法に大きな変更はありません
- コマンドライン引数による設定には対応していません

### 動作変更に関する注意

以前のバージョンで、区切り行を伴わない`|`入りの通常文がテーブルとして出力されていた場合、v2.4.0では通常段落として出力されます。これはテーブル誤認を防ぐための意図的な変更です。
