# v3.0.0 リリースノート

- リリース日: 2026-09-22
- 前バージョン: v2.4.0

## 概要

v3.0.0では、Markdown解析・Excel描画・状態管理・設定UI・ファイル入出力の大規模なリファクタリングを行いました。

ネストした引用内コードブロックや、引用深度が変化するテーブルの不具合を修正したほか、設定画面を1つのフォームへ統合し、出力ファイルの安全性と保守性を改善しています。

また、過大な列数によるメモリ消費を抑えるため、設定可能な最大列数を256列へ変更しました。

v2.4.0から公開Java APIに後方互換性のない変更が含まれるため、メジャーバージョンを更新しています。

---

## 主な変更点

### ネストした引用内コードブロックの修正

2段以上の引用内にあるコードブロックを正しく解析・描画できるようになりました。

例えば、次のMarkdownを処理できます。

````markdown
> > ```text
> > code
> > ```
````

2段引用の場合、Excel上では次のように配置されます。

| 列 | 用途 |
|---|---|
| B列 | 1段目の引用装飾 |
| C列 | 2段目の引用装飾 |
| D列 | コードブロック枠 |
| E列 | コード本文 |

開始時の引用深度分だけ引用マーカーを除去するため、それを超える `>` はコード本文として保持されます。

閉じフェンスがないままEOFへ到達した場合も、コードブロックの外枠を完成させます。

---

### テーブルの状態遷移を修正

テーブルの継続判定で、行種別だけでなく引用深度も考慮するようになりました。

以下の遷移で、各テーブルが別のコンテキストとして処理されます。

- 引用テーブル → 通常テーブル
- 通常テーブル → 引用テーブル
- 引用深度1のテーブル → 引用深度2のテーブル
- 引用深度2のテーブル → 引用深度1のテーブル

これにより、後続テーブルが直前のテーブル本文として誤って扱われる問題を修正しました。

---

### 設定画面を1つのフォームへ統合

従来は、ファイル、列数、フォント、縦位置、フォントサイズを個別のダイアログで入力していました。

v3.0.0では、以下の項目を1つの設定フォームで編集できます。

- Markdown入力ファイル
- Excel出力ファイル
- シート全体の列数
- フォント
- セルの縦位置
- `#` 見出しのフォントサイズ
- `##` 見出しのフォントサイズ
- `###` 見出しのフォントサイズ
- 通常テキストのフォントサイズ

Markdownファイルを選択すると、入力ファイルと同じディレクトリにある `.xlsx` パスが出力先として自動設定されます。

#### キャンセル動作

以下の操作では、設定処理全体を中止します。

- 設定フォームの「キャンセル」
- ウィンドウの閉じるボタン
- Escキー

設定フォーム内のファイル参照ダイアログだけをキャンセルした場合は、設定フォームへ戻ります。

---

### シート列数の上限を256列へ変更

設定できるシート全体の列数を、次の範囲へ変更しました。

```text
3～256列
```

`.xlsx`形式自体は最大16,384列まで対応していますが、本ツールでは引用、コードブロック、水平線などの描画時に、描画範囲全体へセルを生成する場合があります。

メモリ消費と処理時間を抑えるため、アプリケーション上の設定上限を256列としています。

既定値は従来どおり40列です。

#### 40列指定時

| 範囲 | 用途 |
|---|---|
| A～AN列 | シート全体 |
| A列 | 左余白 |
| B～AM列 | Markdown描画範囲 |
| AN列 | 右余白 |

#### 256列指定時

| 範囲 | 用途 |
|---|---|
| A～IV列 | シート全体 |
| A列 | 左余白 |
| B～IU列 | Markdown描画範囲 |
| IV列 | 右余白 |

---

### 出力ファイルを安全に置換

Excelファイルを出力先へ直接書き込まず、次の手順で出力するようになりました。

1. 出力先と同じディレクトリに一時ファイルを作成
2. 一時ファイルへWorkbookを書き込み
3. 書き込み成功後に最終出力ファイルへ移動
4. 失敗時は一時ファイルを削除

ファイルシステムが原子的な移動に対応している場合は、原子的な置換を使用します。対応していない場合は、通常の置換処理へフォールバックします。

これにより、書き込み途中の失敗で既存ファイルが不完全な内容になる可能性を低減しました。

---

### エラー処理を改善

`main()` で変換処理中の例外を捕捉するようになりました。

エラー発生時は、次の処理を行います。

- 詳細なスタックトレースを標準エラーへ出力
- ユーザー向けエラーダイアログを表示
- 終了コード `1` で異常終了

正常終了および設定フォームのキャンセルでは、終了コード `0` になります。

完了・エラーダイアログはSwingのEDT上で表示します。

---

## 内部設計の改善

### `RenderState` の分割

描画状態を1つの巨大なクラスで管理せず、責務ごとの状態オブジェクトへ分割しました。

主な状態オブジェクトは次のとおりです。

- 描画位置・行番号
- リスト状態
- 引用状態
- コードブロック状態
- テーブル状態

`RenderState` は、これらを調整するファサード兼状態遷移コントローラーになりました。

---

### Markdown行情報の再設計

`LineInfo` と `LineKind` を `MarkdownRenderer` の内部型から分離しました。

また、引用を再帰的な `LineInfo` として保持する方式を廃止し、次の情報を明示的に保持する方式へ変更しました。

- 引用深度
- 入力Markdown上の行全体
- 引用マーカー除去後の内容
- 引用マーカー除去後のインデント
- 実際のMarkdown行種別

例えば2段引用内の見出しは、概念的に次のように表現されます。

```text
kind = HEADING
quoteDepth = 2
raw = "> > ### heading"
contentRaw = "### heading"
```

---

### レンダラーをブロック種別ごとに分割

`MarkdownRenderer` に集中していた処理を、専用レンダラーへ分割しました。

- コードブロック
- 引用
- 見出し
- 水平線
- テーブル

`MarkdownRenderer` は、行解析、段落管理、境界処理、専用レンダラーの呼び出しを担当します。

---

### 入出力とWorkbook描画を分離

`MarkdownToExcelConverter` の責務を次のクラスへ分割しました。

- UTF-8 Markdownファイル入力
- WorkbookへのMarkdown描画
- 一時ファイル経由のExcel出力
- 各処理の調整とリソース管理

これにより、ファイル入出力を伴わずにWorkbook描画だけをテストできるようになりました。

---

### `XSSFWorkbook` への型統一

出力形式が `.xlsx` 固定であり、XSSF固有機能を利用していることを明確にするため、Workbookの所有型を `XSSFWorkbook` に統一しました。

フォントキャッシュも `XSSFFont` を使用するようになり、不要なキャストを削除しています。

---

### 設定値を値オブジェクトへ分割

設定を次の値オブジェクトへ分割しました。

- `MdFontSettings`
- `MdSheetSettings`
- `SheetColumnLayout`

フォント設定、シート設定、実際の描画列範囲の意味を明確化しています。

---

### Markdown字句解析の共通化

重複していた解析処理を共通化しました。

- ASCII punctuation判定
- 番号付きリストマーカー解析
- コードフェンス解析

独自Markdownパーサーは引き続き使用します。対応構文と制限事項は、`docs/markdown-support.md` を参照してください。

---

### スタイル生成処理の分割

`MdStyleCatalog` の巨大なコンストラクターを、次のスタイルグループ単位へ分割しました。

- 見出し
- 通常テキスト・空行・リスト
- コードブロック
- 水平線
- テーブル
- 引用

コードブロック外枠のビットマスクも専用定数へ置き換えています。

---

### 未使用コードの整理

以下を含む未使用コードや役割の薄い処理を削除・統合しました。

- 未使用のセル追記ユーティリティ
- 未使用の引用状態遷移
- 未使用のMarkdown文字列処理
- 旧互換用インラインAPI
- 未使用のフィールド・getter・コンストラクター
- 水平線専用の薄いユーティリティクラス
- テーブル終了処理の未使用引数

---

主な確認対象は次のとおりです。

- インラインMarkdown解析
- ASCII punctuation
- 番号付きリストマーカー
- コードフェンス
- フォントキャッシュ
- スタイルカタログ
- 列範囲
- 設定値オブジェクト
- UTF-8 Markdown入力
- ファイルを使用しないWorkbook描画
- 出力ファイルの安全な置換
- 置換失敗時の一時ファイル削除
- ネスト引用内コードブロック
- ネスト引用内コードブロックのEOF終了
- 引用コードブロックから引用段落への遷移
- ネスト引用から外側の引用への遷移
- ネストリストからルートリストへの遷移
- 通常テーブルと引用テーブル間の遷移
- 引用深度が異なるテーブル間の遷移

## 後方互換性のない変更

v3.0.0には、v2.4.0のJava APIと互換性のない変更があります。

GUIから利用する場合、通常はコード変更不要です。Javaコードから各クラスを直接利用している場合は、移行が必要です。

### `Md2ExcelConfig` の変更

入力・出力パスの型を `String` から `Path` へ変更しました。

また、フォント設定とシート設定を値オブジェクトへ分割しました。

#### v2.4.0

```java
new Md2ExcelConfig(
        "input.md",
        "output.xlsx",
        40,
        "Meiryo",
        16,
        14,
        12,
        11,
        VerticalAlignment.BOTTOM);
```

#### v3.0.0

```java
new Md2ExcelConfig(
        Paths.get("input.md"),
        Paths.get("output.xlsx"),
        new MdFontSettings(
                "Meiryo",
                16,
                14,
                12,
                11),
        new MdSheetSettings(
                40,
                VerticalAlignment.BOTTOM));
```

パスは次のアクセサーから取得します。

```java
config.getInputPath();
config.getOutputPath();
```

---

### `LineInfo` の変更

以下の変更があります。

- `MarkdownRenderer` の内部型から独立クラスへ移動
- 11引数コンストラクターを廃止
- 行種別ごとの名前付きファクトリを導入
- 再帰的な引用情報を廃止
- `BLOCK_QUOTE` 行種別を廃止
- 引用深度と引用内容を直接保持

旧APIの次のメソッドは使用できません。

```java
getQuotedContent()
getInnermostQuotedContent()
```

引用は次のAPIで確認します。

```java
line.isQuoted();
line.getQuoteDepth();
line.getContentRaw();
line.getContentTrimmed();
line.getContentIndent();
```

---

### `RenderContext` の変更

列数と開始列を個別に渡すコンストラクターを廃止し、`SheetColumnLayout` を渡す形式へ変更しました。

また、Workbook型を `XSSFWorkbook` に統一しています。

---

### 最大列数の変更

設定可能な最大列数を次のように変更しました。

```text
v2.4.0: 16,384列
v3.0.0: 256列
```

256列を超える設定を使用していた場合は、256列以下へ変更してください。

---

### 削除されたクラス・メソッド

未使用または旧互換用だった複数のクラス・メソッドを削除しています。

Java APIを直接利用している場合は、コンパイルエラーを確認し、新しい描画・解析APIへ移行してください。

---

## アップグレード時の注意

v2.4.0からアップグレードする場合は、次を確認してください。

1. シート全体の列数が256以下であること
2. Javaコードから `Md2ExcelConfig` を生成している場合は新コンストラクターへ移行すること
3. `LineInfo` や `RenderContext` を直接使用している場合は新APIへ移行すること
4. 設定画面が単一フォームへ変更されていること
5. 出力先と同じディレクトリに一時ファイルを作成できる権限があること

出力ファイルの置換には、出力先ディレクトリへの作成・移動・削除権限が必要です。

## Markdown対応仕様

本ツールは独自Markdownパーサーを使用しています。

CommonMarkやGFMの完全互換実装ではありません。対応している記法と意図的な差異については、以下を参照してください。

- `README.md`
- `docs/markdown-support.md`

---

## 既知の制限事項

以下は引き続き未対応です。

- リンク
- 画像
- 打ち消し線
- タスクリスト
- インデント形式のコードブロック
- `<br>`以外のHTML描画
- CommonMarkおよびGFMの全構文
- コマンドライン引数による設定
- headless環境での設定GUI

コードブロックは、バッククォートまたはチルダによるfenced code blockのみ対応しています。
